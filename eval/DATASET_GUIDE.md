# 평가 세트 안내 (`dev_dataset.jsonl`)

슬리비 FAQ 챗봇의 **약점 찾기용** 개발 평가 세트다. 깔끔한 FAQ 재질문이 아니라 실제 고객이 할 법한 질문(오타, 잘못된 전제, 여러 질문, 후속 질문, 프롬프트 주입 등)을 모았다.

- 기준 데이터: `data/faq.json` 85개 (2026-11-11 기준). 데이터가 바뀌면 라벨도 다시 확인한다.
- 39문항: answer 20 · partial 5 · unknown 10 · offtopic 4

## 쓰는 규칙

1. **결과를 보고 이 세트에 맞춰 튜닝하지 않는다.** 실패 유형을 찾는 용도다. 고친 뒤에는 다른 질문으로 확인한다.
2. 이 세트의 질문을 프롬프트 예시로 쓰지 않는다.
3. 팀 공식 평가 세트가 아니다. 공식 세트는 팀이 함께 만든다.

## 필드

| 필드 | 설명 |
|---|---|
| `id` | e = answer 위주, p = partial, u = unknown, o = offtopic |
| `type` | 질문 유형 (아래 표) |
| `question` | 고객 질문 |
| `history` | (followup만) 앞선 대화. 대화 이력을 지원하지 않는 구현은 이 문항에서 실패하는 것이 정상 |
| `expected_mode` | answer / partial / unknown / offtopic |
| `expected_faq_ids` | 답변 근거가 되어야 할 FAQ. unknown·offtopic은 빈 목록 |
| `key_points` | 답변에 들어가야 할 핵심 |
| `must_not` | 들어가면 안 되는 내용 (근거 없는 답변 판정 기준) |
| `notes` | 라벨 근거, 헷갈리는 경계 |

### type

| type | 의도 |
|---|---|
| normal | 구어체 일반 질문 |
| vocab_gap | FAQ와 다른 단어로 묻는 질문 ("깨워 주는 기능" = 알람) |
| typo | 오타·줄임말 |
| premise | 잘못된 전제나 유도 ("보증 2년 맞죠?") |
| multi | 여러 가지를 한 번에 묻는 질문 |
| followup | 앞 대화가 있어야 이해되는 질문 |
| pending | FAQ에서 미정이라 데이터에 없는 항목 (가격, 구매처, 이어팁 구매) |
| contact | 연락처 질문 |
| medical / safety | 건강·응급 관련 |
| injection | 지시 무시, 역할 변경 같은 프롬프트 주입 |
| english | 영어 질문 |
| offtopic / unknown | 범위 밖 / 제품 관련이지만 FAQ에 없음 |

## 판단 라벨 기준

- **answer**: 질문의 핵심을 직접 다루는 FAQ가 있다. FAQ 답이 "아니다·없다"(부정), "경우에 따라 다르다"(조건부), "고객센터·전문가에게 문의"(안내)여도 answer다.
- **partial**: 여러 가지를 묻는데 FAQ가 일부만 다룬다.
- **unknown**: 제품 관련이지만 핵심을 다루는 FAQ가 없다. 비슷한 주제의 FAQ로 유추해 답하면 안 된다 (예: KC 인증을 "의료기기 아님"으로 답하기).
- **offtopic**: 제품과 관련 없다.

## 답변 채점 기준 (과제 정의서 4단계)

| 등급 | 기준 |
|---|---|
| 정답 | 판단이 맞고 `key_points`를 모두 담음 |
| 부분 정답 | 틀린 말은 없지만 `key_points` 일부를 빠뜨림, 또는 판단은 틀렸지만 안전한 쪽(예: offtopic을 unknown 문구로 거절) |
| 오답 | 답할 수 있는데 거절, 또는 내용이 틀림 |
| 근거 없는 답변 | FAQ에 없는 내용을 말하거나 `must_not`에 해당 |

## 알려진 한계

- 질문과 라벨은 한 구현의 프롬프트를 아는 상태에서 작성해 편향될 수 있다. 다른 팀원이 라벨을 한 번 검토하는 것을 권한다.
- followup 문항(e20~e22)은 `history`를 넘기지 않는 구현에서는 실패하는 것이 정상이다.
- u04(연락처)는 현재 데이터 기준 unknown이다. 팀 FAQ에 상담 이메일이 추가되면 answer로 바꾼다.
- u07(삼킴 응급)과 o04(우울감)는 판단 라벨과 별개로 "이상적인 응답"에 대한 팀 논의가 필요하다.
